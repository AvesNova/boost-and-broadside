# The documentation site: notes

Branch `docs/site`, from `v2` at 49e5e2a9. A MkDocs Material site in `docs/`, with the
reference generated by mkdocstrings and tables generated from `bnb` at build time, and
checks under `tests/docs` that make stale docs fail the suite. Nothing under `src/`,
`bench/`, `tests/` outside `tests/docs/`, or `docs/rewrite/` (but this file) changed.

## Design

### Site layout

`mkdocs.yml` at the root; pages in `docs/`; `docs/rewrite/`, `docs/hooks/` and
`docs/roadmap.yml` are excluded from the site (`exclude_docs`). Five top-level tabs:

| Tab | Pages |
|---|---|
| Home | `docs/index.md` |
| Getting started | installation, running the tests, a first training run, a benchmark |
| Guides | training (presets, pools, the mixed batch), benchmarking (the lock, cells, sizes), reference fixtures (goldens, adapters, `REFERENCE_ARM`), adding a mode |
| Explanation | architecture; contracts; the game (physics, perception and fog, modes, rewards, mixed batches); Yemong; the training loop; the roadmap; one in-progress page each for the learner, ship card, scripted agent, BC, league, diagnostics, play shell |
| Reference | one page per package: `bnb.contracts`, `bnb.game`, `bnb.controllers`, `bnb.models`, `bnb.learn`, `bnb.runtime`, `bnb.cli`, `bench` |
| Contributing | `docs/contributing/writing-docs.md` |

- Each reference page is one `::: package` directive with `show_submodules: true` and
  `show_if_no_docstring: true`, so a new module or function appears without editing the page,
  with its signature even when it has no docstring.
- `validation:` in `mkdocs.yml` sets every nav and link check to `warn`, so `--strict` fails
  on a page left out of the nav, a broken link or a broken anchor.
- The README is a short entry point: what the project is, the quickstart, links into
  `docs/`, and the `v1-torch-final` line.

### Generated content

`docs/hooks/generated.py` is an MkDocs hook (`on_page_markdown`). A page asks for a block
with a line of its own, `<!-- generated: NAME -->` (renamed from `generated-table` in the
fix round), outside a fenced block; the hook replaces it with Markdown built by importing
`bnb` or reading a data file. An unknown name raises and fails the build. The blocks
(`BLOCKS` in the hook; the fix round's additions are listed under "Fix round"):

- the observation's columns: `ship-columns` (with the hidden-zero split from
  `SHIP_HIDDEN_ZERO`), `field-columns`, `zone-columns`, `global-columns`;
- the action layout: `action-layout` (`NUM_POWER`, `NUM_STICK`, `NUM_SHOOT`, `NUM_JOINT`),
  `stick-levels` (`STICK_LEVELS`), `power-modes` (`POWER_MODES`);
- rewards: `reward-levels` (`REWARD_LEVELS` with the `RewardConfig` weights),
  `reward-config`;
- the game: `ship-card` (`ship_types.DEFAULTS`), `game-constants` (`Rules`),
  `flight-constants`, `mode-clocks` (`CLOCKS`), `mode-rules`, `game-presets` (`PRESETS`),
  `game-config`, `pool-fields`;
- training: `training-mix` (`TRAINING_MIX`), `training-lineup` (`LINEUP`), `mixed-pools`
  (`mixed()` with `environment_multiple`), `train-config`, `ppo-config`, `cli-options`
  (`bnb.cli.Train`);
- `yemong-config`, `bench-sizes`, and `roadmap` (from `docs/roadmap.yml`).

Dataclass tables list each field's default and the comment on its line in the source (read
with `tokenize`), so units and spec symbols come from the code too. The roadmap's status
lives only in `docs/roadmap.yml` (section, title, status, spec); the hook validates its
keys, its status vocabulary (merged, specified, decided, planned) and that each spec path
exists.

### Checks (`tests/docs`)

| Check | File | Kind |
|---|---|---|
| 1. strict build into a temporary directory | `test_build.py` | failure; `slow`; skips without the docs group |
| 2. code references resolve | `test_references.py` | failure, naming page and line |
| 3. runnable examples run | `test_examples.py` | failure; `slow` |
| 4. coverage map | `staleness.py`, `test_staleness.py` | warning only |
| 5. docstring report | `docstrings.py` | a command, not a test |

1. `python -m mkdocs build --strict --site-dir <tmp>`. Catches broken links and anchors,
   nav entries without pages and pages without nav entries, unresolved mkdocstrings
   cross-references, and unknown generated tables. About 8 s on the dev laptop while other
   agents loaded the CPU.
2. Per page: every backticked dotted name that starts with `bnb.` or `bench.`, every
   `[text][bnb.x]` cross-reference and every `::: bnb.x` directive imports (module prefix,
   then attributes; dataclass fields and annotated attributes count). Every backticked path
   under `src/`, `tests/`, `bench/` or `docs/` exists, and `path::name` must define `name`.
   Every Python block parses and its `bnb`/`bench` imports resolve, runnable or not. Every
   `python` or `bash` block carries a run marker; every page declares `covers:` and the
   paths exist; every table marker names a known table and every table renders; any other
   `<!-- ... -->` line is rejected, so a misspelt marker cannot silently render nothing.
   These need nothing beyond the base environment (a small front-matter parser instead of
   PyYAML); they run in about 3 s.
3. A block preceded by `<!-- runnable -->` runs from the repository root with
   `CUDA_VISIBLE_DEVICES=""`: Python in a fresh interpreter, commands in `bash -euo
   pipefail`. Every other `python`/`bash` block needs `<!-- not-runnable: reason -->`. There
   are runnable examples for the game API, the action contract, the pools, the bench sizes,
   a tiny eager CPU `Trainer` update, `Realtime`, `bnb --help`, one test file and both
   report commands. About 30 s in total under the same load.
4. Each page's front matter lists `covers: [paths]`. For each page, `git log
   <page's last commit>..HEAD -- <covers>`; any commit found is a `PossiblyStalePage`
   warning in pytest's summary, and `uv run --no-sync python -m tests.docs.staleness` prints
   the same report. Outside a git work tree or in a shallow clone it skips with the reason
   (both checked by hand in scratch clones). A page that was never committed is skipped. A
   page still correct after a code change is confirmed by setting `reviewed: <date>` in its
   front matter and committing it.
5. `uv run --no-sync python -m tests.docs.docstrings` lists public modules, classes,
   top-level functions and public methods of `bnb` and `bench` whose docstring is missing or
   one word. The list is below.

## Decisions and deviations

1. **A small hook, not `mkdocs-macros`.** The markers are HTML comments: invisible on
   GitHub, no template language in the pages, and the tests load the same hook file to
   check table names and render every table without MkDocs installed.
2. **Run markers are HTML comments on the line before the fence,** not fence attributes.
   An attribute on the fence changes how GitHub and Material render it; a comment changes
   nothing. The brief's "mark the rest as not runnable" is enforced: an unmarked
   `python`/`bash` block fails.
3. **Examples run in subprocesses with CUDA hidden,** so a runnable example cannot use the
   GPU, and process state (seeds, threads, dynamo) cannot leak between examples or into the
   suite.
4. **The docs packages are a default dependency group** (fix round, the coordinator's
   decision; first round: an extra, which plain `uv sync` removed). The build test still
   skips with a reason if they are missing; the other checks need only the base
   environment.
5. **The reference shows members without docstrings** (`show_if_no_docstring: true`):
   without it, the `bench` page showed 6 of its 28 objects, and every undocumented
   controller method was missing.
6. **MkDocs is pinned below 2** (`mkdocs>=1.6,<2`). MkDocs 2 is not compatible with Material.
   Material 9.8 prints an end-of-life banner (May 2027; Zensical is its successor); the
   tests set `NO_MKDOCS_2_WARNING=1` to keep their output clean.
7. **`covers:` granularity.** Pages cover the files they describe, not whole packages, so a
   warning means something. The home page covers nothing; the reference and in-progress
   pages cover nothing (the reference regenerates).
8. **Short dotted names are not checked.** Only names starting with `bnb.` or `bench.`
   resolve; `Rules.pools` in prose is not checked. The writing guide says to use the full
   name where it matters.
9. **No hardcoded counts** (a rule the writing guide keeps): prose names the constant or embeds the table
   (`FRONTLINE_ZONES` zones, `len(REWARD_LEVELS)`, `bench.cell.TIMED`).
10. **Measured numbers are quoted only with their source:** the mixed batch's cost (commit
    81f54b32, RTX 4070 Laptop, 4096 environments, from `mixed-notes.md`). No other page
    quotes a measurement.
11. **ruff check, not ruff format.** `ruff check` passes on the new files. The codebase is
    not `ruff format`-clean (66 files would be reformatted), so the new Python follows the
    surrounding hand-wrapped style.
12. **Roadmap statuses** are my reading of the records: merged (0, 1, 3, 3b, 3c, 5),
    specified (1b, 4, 6, 7), decided (8, `league.md`; spec to follow), planned (9, a draft
    audit; 10, no record).
13. **Commit trailers** follow the brief (`Co-Authored-By`), which contradicts
    `STYLE_GUIDE.md` section 8 ("No Co-Authored-By lines").

## Disagreements between docs and code

The code wins; the site follows it. None of these were edited (outside my boundaries).

1. **`src/bnb/cli.py`'s module docstring** says "`bnb train ...`". The command has no
   `train` subcommand: it is `bnb [--preset ...]` (`tyro.cli(Train)`).
2. **`STYLE_GUIDE.md`** is v1's guide and is stale; the site neither links it nor calls it
   current (the writing guide says a v2 code style guide is pending and summarises
   `scaffold.md` sections 3 and 4 and the full-words rule instead). Its symbol table
   contradicts `contracts.md`: `T` is time and `K` is bullets or reward components there,
   while `contracts.md` uses `T` for teams, `L` for steps and `K` for bullet slots per ship. It describes
   v1 code that does not exist in v2:
   `FeatureCoordinator`, `train/rl/features.py` and `build_standard_coordinator()` (6.10),
   `TensorState` and `_make_prev_state_proxy` (6.5), `src/boost_and_broadside/profiles/`
   and `constants.py` (6.3), and "Python 3.13+" (the project requires 3.14). Its section 8
   forbids the `Co-Authored-By` trailer the briefs require.
3. **`scaffold.md` section 5:** "The cut list lives in `runtime/stages.py`." There is no
   such file; the stages are the tuple in `Rollout.__init__` (`src/bnb/runtime/rollout.py`).
4. **`scaffold.md` section 4 (tree):** `config/` (presets, CLI), `models/mlp/`,
   `game/step.py` and a top-level `reference/` do not exist. Presets are in
   `bnb.game.modes.rules.PRESETS`, the CLI is `bnb.cli`, the MLP is `bnb/models/mlp.py`,
   the step is `bnb/game/physics/step.py` behind `bnb.game.api`, and the oracle goldens are
   in `tests/reference/`.
5. **`scaffold.md` section 7:** "`bnb train --preset skeleton`". No `train` subcommand and
   no `skeleton` preset.
6. **`contracts.md` section 1:** `GameConfig` with `tick`, `bullet_slots`, `team_types` and
   `mode: ModeConfig`. In code those are on `bnb.game.rules.Rules`, and `mode` is a string.
   The current-schema section does not correct this.
7. **`contracts.md` section 2:** `Match` with `t`, `seat_of_team`, `last_seen`. In code:
   `episode_tick`, `spawn_axis_x`, `spawn_axis_y`, `ticks_since_seen`, `fogged`; the seat is
   a runtime array.
8. **`contracts.md` sections 6 and 9:** `Privileged` is "written only into the rollout
   buffer", and `Trajectory` has `privileged`, `spawned` and `carry0`. In code the rollout
   discards `Privileged` (`_perceive`), and `Trajectory` has neither `privileged` nor
   `spawned` (`initial_carry` replaces `carry0`, as the current schema says).
9. **`contracts.md` section 7:** `init_carry(batch)` and `unroll` in the `Controller`
   protocol. In code: `init_carry(views, device)`, and no `unroll` in the protocol;
   `YemongController.unroll(carry, obs, replay, reset)` has its own signature.
10. **`contracts.md` section 10:** `reset(cfg, types, gen)`, `observe(cfg, state)`. In code:
    `bnb.game.api.reset(rules, types, uniforms, fogged)` and `perceive(rules, state)`.
11. **`game-spec.md` 10.2:** a hidden ship shows "only alive, visible, respawn, type,
    team_rel, since_seen, spawned". The code also always shows `fired` (`SHOWN` in
    `src/bnb/game/perception/observe.py`); a ship that fired is visible anyway.
12. **`modes-spec.md` sections 1 and 7** (`deathmatch_wide` with 40 fields; team deathmatch
    `Z = 0`) and **`yemong-spec.md` section 4** ("v1's global position code is dropped")
    were superseded by `mixed-spec.md` and the Yemong fix round (10 fields; `Z = 5` in
    every mode; the global token reads the shifted centre's code). The spec texts were not
    amended.
13. **The old README's status** stopped at section 1 ("Section 1 ... is merged ... Every
    section is a stub"); sections 3, 3b, 3c and 5 are merged too. The new README's status
    lists every merged section and points at the roadmap.

## Keeping the docs current (for future briefs)

> **Docs.** The docs in `docs/` and `README.md` are checked by the suite:
> `uv run --no-sync pytest` fails if a backticked name (full, short or a lowercase word), a
> repository path or a `bnb` command option in a page no longer resolves, if a runnable
> example fails, or if `mkdocs build --strict` breaks. Fix those as part of your change. Tables of values from the code (observation columns, reward
> levels, presets, constants) are generated; never copy them into prose. When you change code
> that a page lists under `covers:`, pytest warns `PossiblyStalePage`, already before you
> commit: reread that page and fix it, or set its `reviewed:` date if it is still correct
> (`uv run --no-sync python -m tests.docs.staleness` lists them). When your section merges,
> replace its page under `docs/explanation/in-progress/` with prose (explanation, and a guide
> if it adds a task), set its status in `docs/roadmap.yml`, and follow
> `docs/contributing/writing-docs.md`: say what exists and why, no evaluative adjectives, no
> design history, every number with where it was measured.

## Fix round (after the blind review, 8/10)

All requested changes made; boundaries as before (no `src/`, no GPU).

**Install.** The docs packages moved from the `docs` extra to a `docs` dependency group in
`[tool.uv] default-groups`, so plain `uv sync` keeps them. `site/` is in `.gitignore`.

**Checks.**
1. Every fence must name its language. A fence in `python`, `bash`, `sh`, `shell`,
   `console` or `text`, or whose first word is `uv`, `bnb` or `python`, needs a run marker.
2. Short names resolve against an index built with `ast` over `src/bnb`, `bench`, `tests`
   and the hook (`tests/docs/names.py`): classes, functions, module constants, class
   members and `self.` attributes. A capitalized name or `Class.attr` must name exactly
   one definition (ambiguous: write it in full; `MODES`, `Carry` and `FRONTLINE` are). A
   lowercase word must be a name, attribute, argument or string constant the code uses. A
   bare file name must exist in the repository. Opt-outs the check sees: `{.plain}` after
   the span (not code; attr_list renders it as a class), and `{.nolink}` for a full name the
   reference has no entry for (still checked).
3. Every `bnb ...` line, in fences and code spans, runnable or not, is parsed (with
   backslash continuations) against `bnb.cli.Train`'s fields, and `--preset` and `--mode`
   values against `PRESETS` and `MODES`.
4. `README.md` is a page for the name, path, command, fence and marker checks, plus a
   relative-link check; it may not hold generated blocks.
5. The staleness report also counts uncommitted changes (`git diff --name-only HEAD` and
   untracked files) against `covers:`, unless the page itself has uncommitted changes.
6. The hook links every backticked dotted `bnb.`/`bench.` name to the reference
   (`[`name`][name]`, resolved by mkdocs-autorefs), so the strict build validates each one.
   Only the tuple-assigned constants (`FIGHTER`, the mode name constants) had no entry.
7. The writing guide documents `reviewed:` (never read; it only gives the page a commit) and
   that `mkdocs build --strict -q` exits 0 on warnings (checked: a broken link gives exit 0
   with `-q`, exit 1 without).
