# v1 against v2: tools and features with no v2 section, 2026-11-01

v1's tools, commands and features, each with a verdict:
- **covered:** a merged or specified v2 section does it; the section is named;
- **keep:** nothing in v2 owns it yet, and v2 needs it. The table proposes where it goes;
- **drop:** v2 does without it, with the reason, and who decided it where a decision
  exists.

Sources:
- v1 at tag `v1-torch-final`: `src/boost_and_broadside/`, `scripts/`, `benchmarks/`,
  `docs/`, `checkpoints/`;
- the old side branches;
- v2 at `a1b4bc86`: `decisions.md`, the section specs and the running sections' branches.

Only the coordinator read v1; no section agent did.

## Summary

The training, model, league, diagnostics and play sections cover v1's core. The gaps:

1. **Run infrastructure has no section (keep).** No v2 spec owns:
   - checkpoints and resume;
   - the run directory;
   - the recorded configuration;
   - the training CLI's run options;
   - the startup memory probe (scaffold section 5).

   The league spec (section 5, resuming), the BC hand-off (scripted-BC spec) and the
   diagnostics spec (A9, resume) all assume it. **Proposal:** a small section 11, "runs",
   after section 6 merges and before section 8.
2. **Named-pair evaluation (keep).** `decisions.md` has `bnb head-to-head` for named
   pairs, but the league spec has only the full tournament (`bnb ratings`). **Proposal:**
   add it to the league spec's section 6. It is the same match engine with a fixed pair
   list.
3. **Crossover, the headline gameplay result (keep, needs a decision).** It answers "how
   many scripted ships does a trained fleet of size T beat", with unequal fleets. v2's
   contracts fix equal team sizes. See the decisions below.
4. **Charts and published results (keep, later).** v1 rendered every figure from W&B
   exports into the run's own directory, and the README showed results. v2 has the JSONL
   sink (section 9), but nothing renders it. **Proposal:** a "results" step after the
   first full training run, not now.
5. **Gameplay video (keep, small).** v1's `capture` wrote seeded mp4 clips. **Proposal:**
   the play shell's `--offscreen` frames plus ffmpeg, in play milestone 2 next to
   replays.

Everything else is covered or dropped by an existing decision.

## Decisions for the author

1. **Section 11, "runs"** (gap 1): checkpoints and resume, the run directory and
   `bnb runs`, the recorded configuration, the startup memory probe, provenance for
   offline results, and where checkpoints live (W&B artifacts or the Hugging Face Hub).
   Proposed order: after section 6 merges, before section 8 (the league's resume test
   needs it).
2. **Head-to-head in the league spec** (gap 2): yes or no.
3. **Crossover** (gap 3) needs unequal fleets. Options:
   - **(a)** allow unequal team sizes in the game: a contracts change ("teams equal
     sizes" today);
   - **(b)** keep equal tensor sizes, and start the smaller fleet's extra ships absent
     (dead, no respawn) for the whole match;
   - **(c)** drop crossover.

   (b) needs no contract change and keeps the model's shapes, but every mode must honour
   "absent for the match".
4. **The drop proposals:** `ar-report`, `noise-calibration`, and the smoke command
   becoming tests.
5. **Results and charts** (gap 4) and **gameplay video** (gap 5): confirm "later" and
   "play milestone 2".
